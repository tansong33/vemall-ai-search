# 高质量金标 Query 生产流程

## 1. 先区分两件事

- **Query 文本从哪里来**：真实搜索日志、产品编写的边界样本、AI 生成的扩写。
- **Query 标签由谁确认**：只有经过人类审核并完成冲突仲裁的标签才叫金标。

最有价值的 Query 主体必须来自真实用户日志。AI 适合补齐长尾组合和错别字，不应该替代真实分布。

首批 2,800 条建议组成：

| 来源 | 数量 | 目的 |
|---|---:|---|
| 真实日志分层采样 | 1,800 | 保持真实流量分布 |
| 零结果/低点击/客服转搜 | 500 | 覆盖现有系统难例 |
| 产品经理编写 hard case | 200 | 否定、歧义、边界、品牌类目冲突 |
| AI 按槽位组合扩写后人工验收 | 300 | 补齐稀有组合和表达变体 |

前 2,000 条训练、300 条验证、500 条测试只是 POC 起点。切分必须按 `group_id`，同一原句的改写、同一模板批次、同一会话不能跨集合。

## 2. 三位产品人员的标注角色

- 产品 A（标签负责人）：维护标签手册和反例，担任最终仲裁人。
- 产品 B、C（标注负责人）：独立标注校准集、dev 和 test；训练集可分批单标。
- 三人共同先标同一批 100 条校准集。两两 strict span F1 低于 0.90 时，不扩大生产，先修订手册再重标。

标注员看到预标可能产生锚定偏差。校准集和正式 test 建议隐藏 AI 预标；训练集为了效率可以显示规则/AI 预标，但必须逐字检查边界。

## 3. 一条 Gold 的状态流转

```text
RAW
  → 脱敏、去重、分桶
  → ANNOTATOR_A / ANNOTATOR_B 独立标注
  → 程序检查 offset、未知标签、重叠实体
  → 自动比较两份 span
      ├─ 完全一致：REVIEWED
      └─ 不一致：ADJUDICATION
  → 产品 A 仲裁
  → GOLD + dataset_version
```

每条数据至少保留：

```json
{
  "query_id": "q_000001",
  "text": "给员工买50元以内的膳魔师保温杯",
  "group_id": "g_000001",
  "source": "search_log",
  "quality_level": "gold",
  "review_status": "adjudicated",
  "entities": [
    {"start": 1, "end": 3, "text": "员工", "label": "SCENE"},
    {"start": 10, "end": 13, "text": "膳魔师", "label": "BRAND"},
    {"start": 13, "end": 16, "text": "保温杯", "label": "PRODUCT_TYPE"}
  ]
}
```

`start` 包含、`end` 不包含，并且必须满足 `text[start:end] == entity.text`。

## 4. 如何让 AI 批量生成 Query，但保持可控

AI 生成的是候选 Query，不是金标。建议按一个明确槽位表批量生产：

```text
PRODUCT_TYPE=保温杯
BRAND=膳魔师
SCENE=员工福利
ATTRIBUTE_VALUE=316不锈钢
BUDGET_MAX=80（由规则抽取，不作为 NER 标签）
STYLE=口语/错别字/语序变化/否定/中英文混写
```

每次要求 AI 返回 JSON，其中实体必须带原文字符 span。随后依次执行：

1. JSON schema 校验；
2. offset 与原文一致性校验；
3. 与商品品牌/类目词典交叉检查；
4. 精确去重与相似 Query 聚类；
5. 过滤广告话术、过长句和不符合商城业务的需求；
6. 人工抽检每个生成模板至少 20%，新模板首批 100% 检查；
7. 人工修正过的进入 Silver；双标并仲裁后才能进入 Gold；
8. AI-only 数据不得进入 dev/test。

模型生成提示词、模型版本、温度、词典版本和生成批次都要记录。后续发现某批数据有系统偏差时，才能整批撤回。

## 5. 真实 Query 如何大批量取样

不要简单取访问量最高的前几千条。建议分桶：

- 30% 高频头部 Query；
- 25% 中频 Query；
- 20% 低频长尾 Query；
- 15% 零结果/低点击 Query；
- 10% 业务新增品牌、类目、节日与 B 端限制条件。

每桶再按 query 长度、是否含品牌、条件数量、类目和场景分层。手机号、姓名、地址、订单号和企业敏感词必须在进入标注平台前脱敏。

## 6. 质量门禁

- 数据程序校验错误数必须为 0；
- dev/test 双人标注覆盖率 100%；
- 每周随机复审训练集至少 10%；
- gold 的两两 strict entity F1 建议不低于 0.90；
- 品牌、商品类型各自至少有足够正例，并单独统计长尾/OOV 切片；
- 测试集一经冻结，只能追加新版本，不能为了提高分数修改旧答案。

模型评分采用实体严格匹配：`start/end/label` 三者完全相同才算 TP。程序入口为 `data_evaluate_ner.py`，不要用 token accuracy 代替实体 F1。
